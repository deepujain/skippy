# Engineering Foundations

Skippy is informed by established engineering practice, but is not a summary or
replacement for these works. Each source contributes a useful constraint to the
agent workflow below.

| Source | What Skippy adopts | Where it appears |
| --- | --- | --- |
| *Accelerate* by Nicole Forsgren, Jez Humble, and Gene Kim | Measure delivery and invest in capabilities that improve outcomes, rather than equating activity with progress | Observable finish conditions, measured performance work, and delivery receipts |
| *The DevOps Handbook* by Gene Kim, Patrick Debois, Jez Humble, John Willis, and Nicole Forsgren | Flow, feedback, continual learning, and low-risk change | Reversible units, proportional verification, and reusable lessons |
| *A Philosophy of Software Design* by John Ousterhout | Manage complexity with clear interfaces and coherent ownership | Smallest owning boundary, singular authority, and understandable boundaries |
| *Software Engineering at Google* by Titus Winters, Tom Manshreck, and Hyrum Wright | Treat testing, review, version control, and long-term maintenance as engineering systems | Risk-proportional test plans, delivery gates, and atomic work units |
| *Team Topologies* by Matthew Skelton and Manuel Pais | Make interaction modes explicit and keep cognitive load bounded | Delegation briefs, isolated writers, narrow roles, and one accountable integrator |

The adaptation is deliberately practical. A source only becomes a Skippy rule
when it changes an agent decision, required artifact, validation step, or
delivery claim. The [engineering decision system](engineering-principles.md)
and [playbook library](../playbooks/index.md) are the actionable forms.
